Sicherheitsvorkehrungen:
	- Anwendung per Docker laufen lassen, der Container darf nicht priviligiert sein --privileged, cap_drop: ALL, no-new-privileges)
	- Webserver-Prozess darf nur als eingeschränkter benutzer laufen nicht als root (www-data)
	- Vor den Start ein Snapshot machen damit man es bei bedarf sofort zurücksetzten kann
	- Regelmäßiges Reseten (täglich oder so) auf den Snapshot, CPU und Speicher limits setzen damit die VM nicht überläuft
	- Alles blockieren was von der VM aussgeht
	- Command Injection, File Upload/Inclusion abschalten
	
Logging: 
	- Wer greift an (Land,ASN), womit (User-Agent,Tools), welche Payloads, zu welcher Zeit
	- Reverse Proxy (der alle Request im JSON-Format loggt)
	- ModSecurity mit den OWASP Core Rules im Modus: DetectionOnly (damti jede Request direkt makiert wird als was für ein Angriff damit wir das nicht auswerten müssen)
	- Logs auf nen anderen rechner direkt sendn

Man kann die Vulnerabilites ausschalten indem man die Module löscht. Danach in "dvwa/includes/dvwaPage.inc.php pro rausgenommen Modul eine Zeile
$menuBlocks['vulnerabilities'][] = array( 'id' => 'exec', 'name' => 'Command Injection', 'url' => 'vulnerabilities/exec/' );
Um sicher zu stellen das keine Codeausführung stattfiindet sollte eine custom.ini in /usr/local/etc/php/conf.d/
schreiben, im Compose-File als Volume mit ":ro"
custom.ini:
disable_functions = exec,shell_exec,system,passthru,popen,proc_open,pcntl_exec
allow_url_include = Off
allow_url_fopen = Off
expose_php = Off
Als letztes dann nochmal die Pfade zu den ordner und den Setup Seiten in ngingx ausdrücklich sperren in dem man Im ngingx-Server-Block das einfügt:
location ~ ^/(vulnerabilities/(exec|fi|upload|open_redirect)|hackable/uploads|setup\.php|phpinfo\.php) {
    return 404;
}
Nochmal überprüfen ob das da steht
In config/config.inc.php:
$_DVWA['default_security_level'] = 'low'; oder 'medium'. Das Level gilt global für alle Module.
$_DVWA['disable_authentication'] muss auf false stehen.
Der Datenbankbenutzer soll nur Rechte auf die Datenbank dvwa haben, kein FILE und kein ALL ON *.*.
und ob alles wirklich aus ist:
for m in exec fi upload open_redirect; do
  curl -s -o /dev/null -w "$m: %{http_code}\n" http://localhost/vulnerabilities/$m/
done
